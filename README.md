# ♿ Accessibility Guardian

> Scan any website for WCAG violations. Get plain-language explanations and developer fixes — powered by **Gemma4** running locally via Ollama.

Built for the [DEV.to × Google Gemma 2026 Challenge](https://dev.to/challenges/google-gemma-2026-05-06).

---

## The Problem

Accessibility reports generated by tools like axe-core are technically accurate — but often incomprehensible to developers without a11y expertise. Output like `"color-contrast: Ensures the contrast between foreground and background colors meets WCAG 2 AA contrast ratio thresholds"` doesn't tell you *who* is affected, *why it matters*, or *exactly how to fix it*.

**Accessibility Guardian** bridges this gap using Gemma4 to transform raw WCAG violations into human-readable explanations with actionable code fixes.

---

## How It Works

```
URL input
    │
    ▼
Playwright Chromium (headless browser)
    │   loads the real page, including JS-rendered content
    ▼
axe-core (WCAG audit engine)
    │   finds violations, passes, incompletes
    ▼
Gemma4 via Ollama (local LLM)
    │   explains each violation in plain language
    ▼
Report: CLI · HTML · JSON
```

For each violation, Gemma4 generates:

| Field | Description |
|---|---|
| **Summary** | Plain-language description of the issue |
| **Who is affected** | Screen reader users, keyboard users, people with low vision, etc. |
| **Why it matters** | WCAG criterion + real-world impact |
| **How to fix** | Step-by-step remediation instructions |
| **Code example** | Before/after code snippet |
| **Priority** | P0–P3 based on axe-core impact level |

---

## Why Gemma4?

- **Local execution** — no API costs, no data sent to external servers. Critical for agencies and public institutions handling sensitive content.
- **Privacy-safe** — URLs and page content never leave your machine.
- **Instruction-following** — Gemma4's structured JSON output is reliable enough to parse programmatically.
- **Fast enough** — Local inference on modern hardware processes each violation in ~5-10 seconds, acceptable for a developer tool.

## Installation

**Prerequisites:**
- Node.js 18+
- [Ollama](https://ollama.ai) with `gemma4:latest`

```bash
# 1. Clone and install
git clone https://github.com/your-username/accessibility-guardian
cd accessibility-guardian
npm install

# 2. Install Playwright browser
npx playwright install chromium

# 3. Pull the model (if you haven't already)
ollama pull gemma4

# 4. Start Ollama
ollama serve
```

## Usage

### CLI

```bash
# Scan with AI analysis (default)
node src/cli.js --url https://your-site.com

# Generate HTML report
node src/cli.js --url https://your-site.com --format html --output report.html

# JSON output (for CI/CD integration)
node src/cli.js --url https://your-site.com --format json > report.json

# Skip AI (raw axe-core output, faster)
node src/cli.js --url https://your-site.com --no-ai
```

### Web UI

```bash
node src/server.js
# Open http://localhost:3000
```

Enter a URL, click Scan, watch the live progress as Playwright scans and Gemma4 analyzes. The full HTML report renders inline.

## Output Example

**CLI:**
```
SERIOUS (1)
────────────────────────────────────────────────────────

[color-contrast] Text does not meet minimum contrast ratio

👥 Who is affected: People with low vision, color blindness, or anyone
   viewing in bright sunlight or on low-quality screens
⚠️  Why it matters: WCAG 1.4.3 requires a 4.5:1 contrast ratio for
   normal text. This text has a ratio of ~2.1:1 — failing AA standard.
🔧 How to fix:
   Darken the text color or lighten the background to achieve at least
   a 4.5:1 ratio. Use a contrast checker like https://webaim.org/resources/contrastchecker/
💻 Code example:
   Before: .light-text { color: #aaa; }
   After:  .light-text { color: #595959; } /* ratio: 7:1 */
Priority: P1 - Fix this sprint
```

**HTML report:** Self-contained single file with expandable violation cards, severity color-coding, and code diff blocks.
